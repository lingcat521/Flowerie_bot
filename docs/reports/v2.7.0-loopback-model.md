# 接入本机自建模型（v2.7.0）

> 一句话：把 `DEEPSEEK_API_URL` 指向 `127.0.0.1` / `localhost` / `::1`，`DEEPSEEK_API_KEY` 就可以留空。
> 第三方厂商地址仍然强制要求密钥——只放宽回环这一种情况。

---

## 1. 为什么需要

自建推理服务（Ollama / llama.cpp server / vLLM / LM Studio / Xinference / text-generation-webui）
通常监听在本机回环，**不校验 Authorization**。此前 Flowerie 无条件拼 `Bearer <key>`：

- 空 key 会发出 `Authorization: Bearer `（非法空令牌），部分服务端直接 400/401；
- 启动校验 `validate_config` 又要求 key 非空，本地用户被迫填一个假 key。

v2.7.0 把这两处一起改了：**回环地址允许空 key，且空 key 时不发 Authorization 头**。

## 2. 判定规则（`src/config.py::is_loopback_url`）

| 地址 | 算回环？ | 说明 |
| :--- | :--- | :--- |
| `http://127.0.0.1:11434/v1/chat/completions` | ✅ | 整个 `127.0.0.0/8` 都算 |
| `http://localhost:8000/v1` | ✅ | 主机名精确匹配 |
| `http://[::1]:8080/v1` | ✅ | IPv6 回环（含 `0:0:0:0:0:0:0:1`） |
| `http://192.168.1.5:11434/v1` | ❌ | 局域网不算：服务通常设了密码 |
| `http://10.0.0.7:8000/v1` | ❌ | 同上 |
| `https://api.deepseek.com/chat/completions` | ❌ | 第三方厂商 |

> 域名里出现 `localhost` 字样（如 `example.com/localhost`）不算回环——判定只看 hostname。

## 3. 三入口配置（与既有配置体系同源）

| 入口 | 位置 | 说明 |
| :--- | :--- | :--- |
| 代码默认值 | `src/config.py` | `AI_ALLOW_LOOPBACK_NO_KEY: bool = True` |
| `.env` / 首次释放模板 | `.env_example` + `env_template`（SCHEMA 同源） | 变量名同上，模板里带中文注释与示例 |
| Web UI | 配置页「AI」分组 + 用户状态页徽章 | 可热更新，保存即生效 |

严格模式（回环也必须填 key）：`AI_ALLOW_LOOPBACK_NO_KEY=false`。

## 4. 覆盖范围

所有出站 LLM 请求统一走 `src/utils/llm_headers.py::auth_headers`：

| 链路 | 位置 |
| :--- | :--- |
| 整轮对话 | `ai_client.chat_once` |
| 流式对话 | `ai_client.chat_stream` |
| 工具调用多轮 | `ai_client.chat_with_messages` |
| 视觉识图 | `vision.describe_image` / `describe_image_file` |
| 引战检测 | `toxic_detector.is_toxic` |

规则：key 非空 → `Authorization: Bearer <key>`（与历史完全一致）；key 为空 → 不发 Authorization。

## 5. 配置示例

```bash
# Ollama
DEEPSEEK_API_URL=http://127.0.0.1:11434/v1/chat/completions
DEEPSEEK_MODEL=qwen2.5:7b
DEEPSEEK_API_KEY=

# vLLM / llama.cpp server
DEEPSEEK_API_URL=http://127.0.0.1:8000/v1/chat/completions
DEEPSEEK_MODEL=your-local-model
DEEPSEEK_API_KEY=
```

视觉 / 引战 / 花语记忆（向量、重排）各有独立地址配置，**留空回退用对话模型的地址与密钥**，
所以本机部署通常只配对话模型一处即可。

## 6. 已知边界

- 流式分句（`STREAM_REPLY_ENABLED`）要求服务端支持 SSE；Ollama / vLLM / llama.cpp 均支持。
  llama.cpp 需启动时带 `-cb`/`--cont-batching` 或 `--parallel` 才有稳定增量输出。
- 服务未启动时启动校验仍会失败——那是连不通，不是密钥问题，按日志查端口。
- 局域网（`192.168.x.x`）刻意不放行：那类服务通常有密码，静默放行会掩盖鉴权失败。
- Web UI「用户状态」页会把回环模型标为「本机回环 · 免密钥」，不会误报「未配置 Key」。
