# 花璃 v2.18.0：把"怎么说话"这件事重新做了一遍

这次改动有点多，主要是三块：回复分句重做、表情包全链路、识图路由。顺手删掉两套没人用的机制。

## 分句：只留三条规则

之前的分句逻辑叠了四层（多条 JSON、边界切分、按空格切、流式），互相打架，还经常把话切碎。现在只剩三条：

1. 超过 100 字：整条发，不拆
2. 不到 40 字：按空格和句末标点拆
3. 中间：整条发

逗号、顿号、小数点、括号不再当切点——之前 `3.5` 会被切成 `3.` 和 `5`，`（气鼓鼓）` 也会被切出来单独成句，很蠢。

一条回复最多拆 3 句，多出来的进缓存，隔 4~6 秒补发。防刷屏，但不丢内容。

## 表情包：三条通道都能用

之前只能靠模型在回复里写 `[STICKER:文件名]`，而且分句关掉时这个标记会**原样发给用户**——群里看到过 `[STICKER:7N07_偷看.gif]` 这种鬼东西，就是这么来的。

现在标记在**解析层**就被剥离，跟分句开关无关。文本一条、图片一条，分开发。

三条通道：

- **文本标记**：模型自己写 `[STICKER:xxx]`
- **概率附图**：被 @ 或叫名字时，10% 概率补一张随机表情包
- **工具调用**：`sticker_search` 搜、`sticker_send` 发，模型自己决定（Web UI「自动化」页开关）

GIF **保留动图**。之前我把 GIF 转成静态 PNG 是错的——官方接口其实吃 GIF，实测 639KB 的动图能正常发出去。真被拒了才降级成首帧 PNG。

索引也修了：支持并发（默认 4 路）和批量上限，几百张表情包不用一次跑完。

## 识图：主模型能自己看就不用外部模型

`VISION_ROUTE_MODE` 三档：

- `auto`：主模型在白名单里 → 自己看图；不在 → 走外部识图模型
- `external`：永远外部
- `native`：强制主模型直看

实测推理型模型单图要烧 500~3000 reasoning tokens，所以直看有**独立预算** `VISION_CHAT_MAX_TOKENS`，不跟聊天的 `DEEPSEEK_MAX_TOKENS` 抢。

另外纯图片消息（没有文字）默认只识图记上下文、**不触发回复**。之前每张图都回一句，群里太吵。

## 删掉的两套机制

- **流式回复**：框架本身不支持 SSE 增量发送，留着是死代码
- **AI 自主多条**（`{"messages":[...]}`）：和分句功能重复，语义还打架

对应配置键一起删了。`.env` 里还留着的话启动时会跳过，不报错。

## 顺手修的

- **@ 召唤绕过节流**：之前连续回 3 条就把群封 60 秒，你在群里喊她完全没反应就是这么回事。现在被 @ 或直接回复消息不受连回上限约束，只有自发接话才限流。
- **接话概率** `REPLY_PROBABILITY`：官方机器人只收 @ 消息，桥接器会给每条都注入 @，所以必须有个概率门才能限频。默认 1.0（必回），桥接部署下调到 0.05。

## 协议层没动

OneBot11 和 Milky 的适配层、传输层一行没改。发图用的还是标准 `image` 段 + `file://` 绝对路径，NapCat 原生支持。

唯一要注意：换回 NapCat 时把 `MENTION_REPLY_GATE_ENABLED` 关掉（默认就是关），真实 @ 才能必回。
